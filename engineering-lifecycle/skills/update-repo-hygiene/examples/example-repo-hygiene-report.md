# Repo Hygiene Report

## Environment Variables

No real secret values were copied. The two new checkout variables are referenced
in code but missing from `.env.example`.

| Variable | Seen In | In `.env.example` | Recommended Stub Value |
| --- | --- | --- | --- |
| STRIPE_SECRET_KEY | api/checkout/session.ts | no | STRIPE_SECRET_KEY=sk_test_replace_me |
| STRIPE_WEBHOOK_SECRET | api/checkout/webhook.ts | no | STRIPE_WEBHOOK_SECRET=whsec_replace_me |
| CHECKOUT_RETURN_URL | api/checkout/session.ts | yes | already documented |

## Gitignore Candidates

| Pattern | Reason | Safe To Add |
| --- | --- | --- |
| `coverage/` | Generated by the test runner, not source | yes |
| `.stripe/` | Local Stripe CLI session cache | yes |
| `*.local.env` | Developer-specific overrides that must never be committed | yes |

## Support File Updates

| File | Reason | Auto-Edit Safe? |
| --- | --- | --- |
| `.env.example` | Add the two missing Stripe variables with placeholders | yes |
| `README.md` | Document the checkout setup and required env vars | yes |
| `CHANGELOG.md` | Record the new checkout flow under Unreleased | yes |

## Risks

| Risk | Impact | Manual Decision |
| --- | --- | --- |
| A developer commits a real `STRIPE_SECRET_KEY` | Credential leak | Confirm pre-commit secret scanning is enabled |
| Ignoring `coverage/` hides a checked-in report someone relied on | Lost CI artifact reference | Verify no tooling reads the committed coverage folder |

## Applied Changes

Added `coverage/`, `.stripe/`, and `*.local.env` to `.gitignore`, and appended
the two missing Stripe variables to `.env.example` with safe stub values.
README and CHANGELOG updates were proposed but left for the owner to approve, so
they were not applied automatically.
